## Honor-декодер: реализация на реальных фото ветров/драконов

### Контекст (из диагностики 7 фото)
Фото качественные (421–623px, чистый фон, чёткие символы). RapidOCR читает 6/7 чисто:
`東→east, 南→south, 西→west, 中→red_dragon, 發→green_dragon`, `white_dragon` — пустой тайл (рамка).
**north_wind**: `raw → 北 ✅`, но `x2 → K`, `x3 → []`. Вывод: безусловный апскейл ломает чтение — нужна мульти-попытка с выбором лучшего результата.

Сейчас `honor.py` — stub (возвращает UNKNOWN / `white_dragon_candidate`). Мапа `HONOR_CHARS` уже в `constants.py`.

### Реализация

**1. `honor.py` — настоящий декодер**
- `decode_honor(crop, suit_confidence, params)`:
  1. **Белый дракон** — если prep-регион почти пуст (fg_ratio < порога) → `white_dragon` (раньше был `white_dragon_candidate`, повышу до уверенного при очень низкой плотности).
  2. **OCR мульти-попыткой**: прогнать OCR на нескольких вариантах — raw, x2, (опц. grayscale) — и собрать все распознанные символы. Безусловный апскейл опускается.
  3. Сопоставить найденные символы с `HONOR_CHARS` (東南西北中發). Если совпало — вернуть honour-класс с `value=None` и label из мапы (`east`/`south`/.../`green_dragon`), confidence = OCR-score.
  4. **Fallback по цвету** (когда OCR нечитаем): red_dragon 中 обычно красный, green_dragon 發 — зелёный. Если на лице тайла доминирует один цвет — использовать это как слабый сигнал.
  5. Иначе → UNKNOWN honor (`label="unknown_honor"`, method=`"stub"` для нераспознанных).

**2. `router.py` — маршрутизация honor на основе OCR**
Сейчас router почти не направляет в HONOR (только fallback в конце). Добавить: после wan-маркера — OCR-проверка на honor-символы (東南西北中發). Если найден → HONOR. Это надёжнее, чем угадывать honour по геометрии (символы иероглифические, как wan).
- Параметр `honor_as_unknown` перестаёт блокировать: раз есть декодер, honour возвращается как самостоятельный результат.

**3. `constants.py` — расширить HONOR_CHARS**
- Добавить `white_dragon` без OCR-маркера (детектится по пустоте, не по символу) — уже структурно учтено.
- Дополнить редко встречающиеся начертания (东/简体, 萬-варианты) для устойчивости.

**4. `types.py` — параметры**
- `honor_fg_ratio_max: float = 0.06` — порог «почти пустой тайл» для white_dragon.
- `honor_ocr_variants: tuple = ("raw", "x2")` — варианты изображений для мульти-попытки.
- `honor_color_fallback: bool = True` — вкл/выкл цветовой fallback.

**5. `ocr_engine.py` — хелпер мульти-попытки** (опционально)
Вынести логику «прогнать OCR на нескольких вариантах, собрать все (text, score)» в функцию `ocr_multi(crop, variants)`, переиспользуемую honor-декодером и потенциально wan-декодером (там та же проблема апскейла).
